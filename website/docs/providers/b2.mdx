## Get started

```bash
cargo add reqsign --features b2
```

```rust
use reqsign::{b2, default_context};

// B2_APPLICATION_KEY_ID and B2_APPLICATION_KEY — resolved by the default chain.
let ctx = default_context();
let signer = b2::default_signer(ctx);

// Load the credential first: api_url belongs to the application key and
// selects the account's endpoint.
let credential = signer.credential_for(None).await?;
let uri = format!(
    "{}/b2api/v4/b2_list_buckets?accountId=account-id",
    credential.api_url
);

let mut req = http::Request::builder()
    .method(http::Method::GET)
    .uri(uri)
    .body(())?
    .into_parts()
    .0;

// Sign with the same credential that produced api_url, then send with the
// HTTP client you already use.
signer.sign_with_credential(&mut req, &credential, None).await?;
```

The default chain exchanges `B2_APPLICATION_KEY_ID` and `B2_APPLICATION_KEY`
for a Native API authorization token with the documented v4
`b2_authorize_account` endpoint. The credential carries the authorization token,
the Native API and download base URLs, and the earlier of the 24-hour token limit
and the application key expiration timestamp. `Signer` caches and refreshes it.

The default source and prepended providers fail closed: a provider error is
returned to the caller instead of falling through, so a retryable
`b2_authorize_account` failure stays retryable.

Use `AccountAuthorizationCredentialProvider` for an explicit application key, or
`StaticCredentialProvider` when the caller already obtained the token and base
URLs. Key capabilities and bucket or prefix restrictions are enforced by B2 and
remain server-side.

The signer covers Native API requests authorized by the account token. Creating
upload URLs, requesting download authorization, and using the S3-compatible API
remain the caller's responsibility.
