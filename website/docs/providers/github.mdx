## Get started

```bash
cargo add reqsign --features github
```

```rust
use reqsign::{default_context, github};

// GH_TOKEN/GITHUB_TOKEN, then the GitHub CLI, then anonymous public access.
let ctx = default_context();
let signer = github::default_signer(ctx);

let mut req = http::Request::builder()
    .method(http::Method::GET)
    .uri("https://api.github.com/repos/apache/reqsign/contents/README.md")
    .header("user-agent", "my-application")
    .header("x-github-api-version", "2022-11-28")
    .body(())?
    .into_parts()
    .0;

// Sign in place, then send with the HTTP client you already use.
signer.sign(&mut req, None).await?;
```

The default chain reads `GH_TOKEN` before `GITHUB_TOKEN`. If neither is set
and the context has a `CommandExecute` adapter, it asks the GitHub CLI for the
stored GitHub.com token with
`gh auth token --hostname github.com --no-refresh`. The command runs directly,
never through a shell; the explicit host keeps discovery independent of
`GH_HOST` and local Git remotes; and `--no-refresh` keeps discovery read-only.
Reqsign does not parse the CLI's configuration files; the CLI remains the source
of truth for account and host selection. If the stored token has expired, run
`gh auth refresh` to renew it, then recreate the signer so it loads the new
token.

With no token, the chain ends with anonymous access. Anonymous requests carry no
`Authorization` header, can read public resources, and are subject to GitHub's
60-requests-per-hour unauthenticated rate limit. Remove the fallback with
`.no_anonymous()` when every request must be authenticated.

## Explicit credentials

Replace the provider for a token managed by your application:

```rust
use reqsign::github::{StaticCredentialProvider, default_signer};

let ctx = reqsign::default_context();
let signer = default_signer(ctx)
    .with_credential_provider(StaticCredentialProvider::new("github-token"));
```

The builder exposes one positive method and one removal method per slot:

```rust
use reqsign::github::DefaultCredentialProvider;

let provider = DefaultCredentialProvider::builder()
    .no_env()
    .no_gh_cli()
    .build();
```

Removed slots are not re-enabled during `build()`. `.env(provider)`,
`.gh_cli(provider)`, and `.anonymous(provider)` replace a slot, while
`push_front` and `with_chain` compose a provider in front of or instead of the
default chain.

## Request behavior

`RequestSigner` adds only a sensitive `Authorization: Bearer` header. It does
not add or replace `User-Agent` (GitHub requires the caller to send one),
`Accept`, or `X-GitHub-Api-Version`, so keep those request headers in the
caller. GitHub has no query authentication, so signing rejects `expires_in`.

## Host and scope

This provider targets GitHub.com and `https://api.github.com`. It ignores
`GH_HOST`, `GH_ENTERPRISE_TOKEN`, and `GITHUB_ENTERPRISE_TOKEN`; use
`StaticCredentialProvider` or a custom provider for GitHub Enterprise Server.
`GH_TOKEN` and `GITHUB_TOKEN` are interpreted as the GitHub CLI's GitHub.com
token; pass the intended token explicitly when you use multiple hosts. GitHub
assigns each token's host and its OAuth scopes or fine-grained repository
permissions. Reqsign neither requests nor inspects them, and it does not
implement GitHub App installation-token exchange.

The caller owns the HTTP client and its redirect policy. Do not forward the
signed `Authorization` header to a different host.
