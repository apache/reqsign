## Get started

```bash
cargo add reqsign --features http-message-signatures
```

RFC 9421 leaves the signature label and covered components to the
application, so there is no default signer. Assemble the policy explicitly:

```rust
use http::header::HeaderName;
use reqsign::http_message_signatures::{
    Component, Credential, RequestSigner, StaticCredentialProvider,
};
use reqsign::{Signer, default_context};

let ctx = default_context();
let request_signer = RequestSigner::new(
    "sig1",
    [
        Component::Method,
        Component::Authority,
        Component::Path,
        Component::Header(HeaderName::from_static("content-digest")),
    ],
)?;
let signer = Signer::new(
    ctx,
    StaticCredentialProvider::new(Credential::hmac_sha256("my-key", b"shared secret")?),
    request_signer,
);

let mut parts = http::Request::builder()
    .method("POST")
    .uri("https://example.com/upload?part=1")
    .header("content-digest", "sha-256=:...:")
    .body(())?
    .into_parts()
    .0;

signer.sign(&mut parts, None).await?;
```

## Scope

This first version signs request heads with HMAC-SHA256 or
RSASSA-PKCS1-v1_5 SHA-256. It supports ordinary request fields and the
`@method`, `@target-uri`, `@authority`, `@scheme`, `@path`, and `@query`
derived components. Percent escapes, query order, and repeated query
parameters are preserved.

Verification, response signing, multiple signatures in one call, component
parameters, `@request-target`, and body I/O are out of scope. To cover a body,
compute a `Content-Digest` before signing and include it in the component list.

HMAC uses raw shared-key bytes. RSA accepts unencrypted PKCS#1 or PKCS#8 PEM
and uses the context's `CryptoProvider`. The RustCrypto provider supports RSA on
native targets but returns `ConfigInvalid` for it on `wasm32-unknown-unknown`;
the HMAC path works on WASM.
