## Get started

```bash
cargo add reqsign --features azure
```

```rust
use reqsign::{azure, default_context};

// Shared key, SAS, or Entra ID (client secrets, workload identity,
// managed identity, Azure CLI) — resolved by the default chain.
let ctx = default_context();
let signer = azure::default_signer(ctx);

let mut req = http::Request::builder()
    .method(http::Method::GET)
    .uri("https://myaccount.blob.core.windows.net/my-container/my-blob")
    .body(())?
    .into_parts()
    .0;

// Sign in place, then send with the HTTP client you already use.
signer.sign(&mut req, None).await?;
```

## Azure API keys

The `azure` feature also exposes `reqsign::azure::api_key` for Azure APIs that
accept a key in a request header. Assemble a `Signer` with a static key or a
caller-named environment variable and select the header required by the API.
When the key rotates, create a new signer or call `with_credential_provider`
with a provider for the rotated key. See the [signing example](https://docs.rs/reqsign/latest/reqsign/azure/index.html#azure-api-keys).
